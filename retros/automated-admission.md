# Automated admission — the pipeline now emits the artifact, not just the verdict

`law-proposer-extensions.md` ended the discovery loop at a ranked
SHIP/no-ship report; `law-shape-aware.md` and
`law-softmax-fold-shipped.md` then recorded the *last human step* —
hand-writing the `R(...)`, its `check`/`derive` hooks, the test
module, and the registration line into `catopt_core/laws/tensor.py`.
That step is now emitted by the pipeline itself.  Closing the loop is
`pipeline --emit-admission <candidate>` → a reviewable patch, not
hand-writing.

The new machinery is `tools/law_emit.py`, wired into
`tools/law_pipeline.py` as `--emit-admission <name> --out <dir>`:

* the proposal's pattern trees render as `Op.make` calls with
  metavar / `$attr:`-metavar leaves (the same spelling `select_mul` /
  `softmax_fold` carry in `tensor.py`);
* `check`/`derive` hooks are transcribed **verbatim** from the
  proposer's named functions — `inspect.getsource` + a def-name
  round-trip check — never lambdas (emission refuses a hook with no
  honest source spelling);
* a generated `tests/test_admitted_<law>.py` covers the
  match/instantiate round-trip, hook unit tests, firing +
  RHS-is-member, **measured** declines, and an end-to-end
  fire → cost-delta → cert-replay → `sink.verify` on the model the
  candidate fired on (the model term serialized into the test, feeds
  regenerated by name);
* `admission_<law>.patch` — a unified diff inserting the law block +
  a `SIMPLIFICATION_RULES` registration line into `tensor.py` plus
  the new test file — a *report for human review, not a mutation*.
  `admitted_<law>.py` is the same block as a standalone importable
  module so the artifact can be compiled and diffed against the
  library before anything is applied.  Nothing under `packages/` was
  touched.

Reproduce:

    .venv/bin/python tools/law_pipeline.py --holdout softmax_fold \
        --emit-admission recognize:softmax --out /tmp/admission

CPU-only, ~6 min (the pipeline run dominates; emission adds seconds).

## 1. The emitted-vs-handwritten comparison (the acceptance test)

Both shipped machine-discovered laws are admitted, so the pipeline
reports `recognize:softmax` as `duplicate` — nothing new to emit.
The validation is therefore held out: `--holdout softmax_fold` makes
`recognize:softmax` SHIP-able again, and it ranked **#1 of 50, SHIP**
(identical evidence to the shipped run: `fires=1 paid=1 drop=19.0%
cert=pass enode=1.06x`, held-out verdict PASS).

The emitted `RECOGNIZE_SOFTMAX` is **functionally identical to the
hand-written `SOFTMAX_FOLD`**:

* **Same pattern** — `law_proposal._key` alpha-normal keys are
  equal (same shape up to metavar naming: `U`/`RD`/`RK`/`SD` vs
  `u`/`RD`/`RK`/`SD`).
* **Same hooks** — the emitted `_check_sum_keepdim` /
  `_derive_softmax_dim` are verbatim transcriptions of the proposer's
  defs; `__code__.co_code` is *byte-identical* to the shipped hooks,
  and 0 diffs on a 21-binding battery (tuple/int/multi-axis/dimless
  dims × keepdim True/False/None).
* **Same behaviour** — on the real `ManualSoftmaxAttention` export:
  1 firing each, identical extracted term
  (`softmax(div(matmul,…),dim=-1)`), identical cost `1.481e5`.
* **Surface syntax differs** — the rule name is `recognize_softmax`
  not `softmax_fold`, `law=` is a `TODO(reviewer)` placeholder, and
  the proposer's longer hook docstring rides along.  Naming and
  prose are explicitly the review step; the math is not.

Applied to a throwaway copy of `tensor.py` (the emitted patch,
`git apply --check`-clean) and loaded as `catopt_core.laws.tensor`
under a sandboxed import, the generated test module passes **9/9**:
round-trip, check-accepts, derive-produces, fires + RHS-member,
`RD`-extended decline, `RK`-flip decline, `RD`-scalar accepted
variant, `U`-mismatch decline, and the e2e on the model export.

A second held-out class also emits and passes (**7/7**): the
hook-free `census:mul_select` naturality law on `SelectiveSSM` —
the shared-attr-metavar case.  Its *accepted variants* are the
instructive part: perturbing a **shared** `dim`/`index` binding
(`dim+1`, `index+1`) still fires — measured, not assumed — while the
declines are the attr-*mismatch* terms (second select's `dim`/`index`
broken), structurally the same tests a human wrote for `select_mul`.

## 2. What the emitter can and cannot admit

**Emittable today:** any SHIP candidate whose pattern trees use
`Op`/`str`-metavar/`Var`/`Param`/`Const` leaves and literal attr
values, with `check`/`derive` as named module-level functions (or
absent).  That covers every proposer family in the pool: census
naturality, mixed-view, pattern recognition, shape-aware schemas,
algebraic grammar.

**Refused honestly** (`Emission.emitted=False` + reason, exit 1):

* non-SHIP candidates (the first failed gate is the reason, same as
  the report's "why not" column) and unknown names;
* hooks with no source-level `def` — lambdas, `partial`s, closures,
  builtins.  The proposer must carry the side condition as a named
  function for it to be transcribed;
* terms carrying unspellable pieces — non-literal attr values
  (round-tripped through `ast.literal_eval(repr(v))`), non-kwarg
  attr keys, unknown-dim feeds (no honest `torch.randn`), an input
  name bound to two different types;
* candidates needing a **novel side condition the proposer did not
  carry** — the deepest limit: the emitter transcribes what the
  proposal knows.  A law that is true only under a shape guard
  nobody wrote is a proposer gap, not an emitter gap — it ships as
  an unconditional `R(...)` only if the pipeline's own gates
  (numeric oracle + `sink.verify`) already cleared it, and the
  review checklist says so.

**Deliberately not automated:** the `law=` prose, the name (the
sanitized candidate label `recognize_softmax`, not `softmax_fold`),
the tag set (`_SIM` default — an expansive law would belong in
`CATEGORICAL_RULES`; the closure gate makes a SHIP-expansive
unlikely, not impossible), and hook-name collisions (a `def`
shadowing an existing `tensor.py` hook is flagged in the summary —
in the holdout case the emitted defs are identical to the shipped
ones and collapse).

## 3. Emission mechanics worth noting

* **Declines are probe-measured, not templated.**  The emitter
  perturbs every `$attr:` binding (bool flip, int +1, tuple extend /
  scalar-unwrap), runs `check` and a bare-e-graph firing on each,
  and emits a test only for the measured outcome — a `False` check
  or a non-firing term becomes a decline, a still-firing term
  becomes an *accepted variant* (the `dim=-1` int-spelling test the
  human wrote for `softmax_fold` falls out mechanically).  Repeated
  metavars get structural mismatch terms: leaf metavars rebound to a
  fresh `Var`, attr metavars broken at their second position — the
  `u≠v` and `dim`/`index`-mismatch declines, exactly as hand-written.
* **Serialization is lossless** for the corpus: `Op.make` trees,
  `Var`/`Param`/`Const` leaves, `repr()`-round-tripped attrs; the
  emitted `_MODEL_TERM` compares `op_repr`-equal to the real export.
  Inputs are keyed by *name* — a `Var` leaf occurring N times is one
  input (the SelectiveSSM export carries six `x` leaves; emitting
  six feeds silently unbound `x`, caught as a `sink.verify` failure
  and fixed).
* **Hooks transcribe verbatim.**  The first implementation renamed
  hooks to `_check_<law>` and hit a transcription failure in the
  real `__main__` run that never reproduced in tests; verbatim
  emission under the proposer's own names is both more faithful
  (they mirror the shipped shapes) and removes the fragile step.
  A def-name sanity check + in-memory `ruff format` + `compile()` on
  every artifact guards what remains.

## 5. Where this leaves the loop

Discovery → verdict → artifact is now one command; the human reviews
a diff instead of writing code.  The remaining manual surface is
deliberately small: the `law=` sentence, the rule name, the tag set.
The next extension is on the *proposer* side — a recognizer for the
un-recognized chains (`(mul, add, rsqrt)` RMSNorm, SwiGLU/GEGLU —
`law-proposer-extensions.md` §4), where the proposer must also carry
the `check`/`derive` the emitter will then transcribe verbatim.
